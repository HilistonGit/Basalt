# Basalt 0.6.6

Десктопный клиент Xray + sing-box с приоритетом Windows 8 / 8.1.
Это проверочная сборка с TUN, а не сертифицированный релиз для старых ОС.

## DNS и IPv6 в 0.6.6

- Исправлено несоответствие: при отключённом IPv6 полный профиль подписки мог возвращать AAAA-записи, хотя TUN блокировал IPv6-соединения. Сгенерированный DNS теперь учитывает переключатель IPv6; исходный документ подписки не изменяется.
- Проверено на выбранном Hysteria2-сервере: после исправления AAAA-запросы Google дают пустой ответ при отключённом IPv6, HTTPS к google.com и www.google.com проходит через TUN. Сам заявленный сбой браузера в отдельных HTTPS-тестах не воспроизведён; это исправление подтверждённого несоответствия DNS, а не доказательство устранения всех причин браузерного сбоя.
- 94 проверки модели и UI-регрессии. В TUN smoke suite добавлен полный нативный Xray-профиль с DNS, дополнительно к профилям Happ.
- После обновления завершите старый клиент через трей и полностью перезапустите браузер, чтобы исключить его прежние DNS/QUIC-соединения.

## Исправление потери правил в 0.6.5

- Полные правила из тела Xray/sing-box/Clash подписки больше не заменяются сокращённым Happ-профилем из HTTP-заголовка routing. Заголовок сохраняется отдельно для метаданных геофайлов. Для подписок из share-ссылок правила по-прежнему берутся из Happ-заголовка.
- Исправление проверено на ответе провайдера: все пять серверов сохраняют 6 правил и 118 доменных записей вместо сокращённого списка из 37. DNS и правила BitTorrent сохраняются из полного конфига.
- Нужно один раз обновить подписку: сохранённый старой версией сокращённый профиль сам по себе не содержит потерянных записей.
- 90 проверок, включая регрессии при совместном наличии полного JSON/YAML и Happ-заголовка; реальные полные конфиги проверены ядрами.

## Исправление split tunneling в 0.6.4

- Удалено завершающее catch-all правило Happ: оно мешало второму проходу IPIfNonMatch и проверке GeoIP. GlobalProxy теперь задаёт outbound по умолчанию, не прерывая поиск правил.
- Добавлен sniffing HTTP/TLS/QUIC в Xray-мосте, чтобы доменные правила работали при получении IP-адреса от TUN.
- Уже маршрутизированные сокеты Xray выходят через прямой outbound sing-box и не попадают повторно в правила подписки. Правило ограничено точным путём выбранного Xray и IPv4 при отключённом IPv6.
- Сетевой регрессионный тест: 2ip.ru по исходной Happ-политике при заведомо недоступном VPN; контрольный сайт вне direct-списка остаётся недоступным. Дополнительный тест IP-правил использует фиксированный DNS и явный /32, не зависит от текущей GeoIP-классификации сайта. Старый 0.6.3 этот сценарий не проходит.
- 84 проверки модели, UI-регрессии. Для применения завершите старую версию через трей и запустите новый полный пакет. Повторный импорт подписки не требуется.

Семантика второго прохода и outbound по умолчанию: [документация Xray](https://xtls.github.io/en/config/routing.html).

- Ручная правка выбранного outbound применяется также при включённых правилах подписки.
- 80 проверок модели, UI-регрессии и сетевые проверки маршрутизации на локальных серверах.

### Границы совместимости маршрутов

Это ещё не полная совместимость со всеми расширениями Clash: MRS, classical rule-provider, fallback-группы, proxy-providers, fallback DNS и respect-rules отклоняются явно. В списках DNS используется первый сервер; параллельный опрос всех серверов Clash пока не воспроизводится. Правила, привязанные к исходным inbound, также требуют адаптации и отклоняются. FakeDNS проходит проверку конфигурации, но отдельного сетевого испытания ещё не было. Неизвестные конструкции нельзя считать поддержанными только по факту успешного импорта.

Испытания на самих Windows 8/8.1 и 32-битной Windows ещё необходимы. Проверки x86-ядер на текущей 64-битной ОС их не заменяют.

## Запуск

Запускайте `build/Basalt.exe` вместе с `Basalt.Core.dll`, `Basalt.exe.config`
и каталогом `cores`. Требуется .NET Framework 4 Full или более новый Framework.
WebView и Node.js не нужны. Ядра и Wintun выбираются автоматически по разрядности ОС.

1. Скопируйте HTTPS-ссылку провайдера и нажмите «Вставить» (или Ctrl+V). User-Agent и HWID задаются один раз в Настройки → Подписки.
2. Выберите сервер внутри группы. В заголовке группы находятся обновление,
   проверка серверов и редактирование. Трафик и срок действия берутся из
   `subscription-userinfo`; при отсутствии данных это явно указано.
3. Выберите режим: TUN для всего компьютера, системный прокси либо прокси для приложений.
4. Нажмите «Подключить». Для TUN Basalt предложит перезапуск с запросом UAC;
   после перезапуска нажмите «Подключить» ещё раз.
5. «Проверить соединение» делает HTTPS-запрос к `www.gstatic.com/generate_204`.
   В TUN запрос выполняется без HTTP-прокси. При split routing контрольный адрес
   может идти напрямую: результат не является проверкой публичного IP.

Новый профиль приложения по умолчанию использует TUN. Существующие настройки
режима сохраняются. Порт HTTP/SOCKS5 — 2080, отдельный HTTP — 2082.
В настройках доступны маршрутизация, обход LAN и процессов, MTU, IPv6, DNS,
порты, доступ к прокси из LAN с обязательным паролем и таймаут проверки серверов.
Проверка группы последовательно запускает ядро для каждого сервера и делает HTTPS
через него; Escape останавливает очередь после текущей операции. Перед проверкой
группы TUN нужно отключить. Проверка обращается только к контрольному адресу.

## Реализовано

- Группы подписок с серверами, трафиком/лимитом, сроком, обновлением и HTTPS-проверкой.
- HTTPS-подписки plain/base64, собственный User-Agent, дедупликация,
  сохранение выбора и отказ от частичного обновления с потерей серверов.
- VLESS TCP/WS/gRPC/XHTTP, TLS/REALITY, Vision на TCP; Trojan через Xray.
- Shadowsocks SIP002 и Hysteria2/salamander через sing-box.
- Для Xray-профилей: TUN или локальный inbound → sing-box → SOCKS5-мост → Xray.
- Wintun, auto_route/strict_route, перехват DNS, выбор DNS для прямых/VPN-доменов,
  явная блокировка IPv6 в TUN при отключённом IPv6.
- Адрес VPN-сервера разрешается до включения TUN и исключается из перехвата;
  отдельный процесс Xray использует этот IP с сохранением исходного TLS SNI.
- Маршруты: всё через VPN, только список или всё кроме списка; домены, суффиксы,
  IPv4/IPv6 CIDR. В TUN также можно направлять процессы по имени exe напрямую.
- Проверка JSON самими ядрами, проверка портов, наблюдение за процессами,
  Job Object для завершения ядер при аварии оболочки.
- Журнал восстановления случайно именованного TUN-адаптера: при остановке/следующем
  запуске оставшийся адаптер отключается. DNS физического интерфейса не изменяется.
- DPAPI и атомарная запись настроек. Восстановление прежнего системного прокси.

Закрытие активного клиента сворачивает его в трей. «Выход» останавливает ядра.
После сбоя TUN может потребоваться запуск от администратора для восстановления.
Это не kill switch: после остановки VPN обычная сеть может снова использоваться.

Настройки: `%LOCALAPPDATA%/Basalt/settings.dat`. Перенос DPAPI-файла другому
пользователю не поддерживается. Временные JSON с ключами находятся в каталоге
runtime этого профиля во время работы и удаляются при остановке/следующем запуске.

## Legacy-ядра

Текущая поставка использует официальные сборки upstream для Windows 7 и новее:

- [Xray 26.10.21](https://github.com/XTLS/Xray-core/releases/tag/v26.10.21): Xray-win7-32.zip и Xray-win7-64.zip.
- [sing-box 1.14.4](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4): windows-386/amd64-legacy-windows-7.zip.
- Wintun 0.14.1. Все архивы проверяются по закреплённым SHA256.

Версии, адреса и SHA256 ядер закреплены в `scripts/legacy-cores.lock.json`.
`fetch-official-cores.ps1` скачивает их в отдельный каталог `build/cores-current`.
Старый способ самостоятельной сборки сохранён только для воспроизведения исторической версии (`build-legacy-cores.ps1 -Historical`); для новой поставки он не используется.

Пакеты `windows-legacy-amd64` и `windows-legacy-386` содержат лицензии и manifest
с SHA-256. Проверка manifest обнаруживает повреждение файлов, но не является
цифровой подписью дистрибутива. Сборка пока не подписана издателем.

## Сборка и проверка

```powershell
.\scripts\fetch-framework-references.ps1
.\scripts\build.ps1
.\scripts\fetch-official-cores.ps1
Copy-Item build/cores-current/* build/cores -Recurse -Force
.\scripts\test-integration.ps1 -Xray build/cores/windows-legacy-amd64/xray.exe -SingBox build/cores/windows-legacy-amd64/sing-box.exe
.\scripts\test-tun.ps1             # только компиляция теста
.\scripts\test-tun.ps1 -Run        # UAC, временный TUN, восстановление сети
```

Сборка оболочки проверена против .NET Framework 4.0 reference assemblies.
69 проверок модели/импорта/конфигураций и интеграции с обоими legacy-пакетами
пройдены на текущей машине. Интеграции проверяют TUN JSON/XHTTP, запуск обоих ядер,
SOCKS5, портовый конфликт, переподключение и DPAPI. Отдельный тест использует
локальный зашифрованный Shadowsocks-сервер и реальный HTTPS.
TUN smoke test на текущем хосте прошёл для Shadowsocks и цепочки VLESS через
Xray: HTTPS без прокси, UDP/DNS, трафик адаптера, переподключение и очистка.
Результат TUN smoke test сохраняется в `build/tun-smoke-result.txt`.

На Windows 8 и 8.1 испытаний пока нет. План для VMware — `docs/compatibility.md`.
XP не поддерживается этим пакетом ядер и Wintun. Другие ограничения: пока нет
автообновления ядер, kill switch,
фрагментации, мультиплексора и отдельного привилегированного сервиса.

## Изменения 0.4.0

Основная тема — тёмная. Исправлено падение пустого списка при индексе 65535;
добавлен UI regression test для наведения, кликов и очистки списка.
Версия продукта 0.4.0, Windows Assembly/FileVersion 0.4.0.0 (четыре поля требуются форматом Windows).
Оболочка x86 запускается на 32- и 64-битной Windows. Универсальный архив включает
оба комплекта ядер; отдельный `-x86.zip` содержит только 32-битные ядра/Wintun и
работает также на x64. Проверки x86 на x64 не заменяют испытания в 32-битной VM.

У каждой подписки есть редактируемый User-Agent с пресетами Basalt, Happ,
v2rayNG, sing-box и Clash Meta. Пресет не означает поддержку формата ответа:
sing-box JSON/Clash YAML поддерживаются начиная с 0.5.0. Добавлен импорт VLESS/Trojan
из Xray JSON (объект или массив), включая транспортные настройки XHTTP.
Из полного JSON извлекаются серверы; inbound и routing провайдера не применяются.
Неподдерживаемые outbound/цепочки приводят к отказу обновления, старый список сохраняется.

HWID: «Авто» передаёт для Happ, «Передавать» — для любого UA,
«Не передавать» — отключает. Заголовки: X-Hwid, X-Device-Os, X-Device-Model.
Идентификатор установки случайный, сохраняется в DPAPI-настройках до первого запроса,
не меняется при перезапуске и не содержит серийных номеров оборудования.
Редирект на другой сервер при включённом HWID блокируется: доверенную конечную
ссылку следует указать явно. Имя компьютера и имя пользователя не передаются.

## Изменения 0.5.0

- Убрана стандартная рамка Windows. Собственная панель: перетаскивание,
  двойной щелчок для разворачивания, resize по краям, свернуть/развернуть/закрыть.
  Обычное сворачивание оставляет окно на панели задач; закрытие активного VPN
  по-прежнему отправляет его в трей. Карточки и кнопки скруглены, добавлены
  стилизованные переключатели и тёмные поля выбора.

  «Обновлять автоматически» и интервал в часах. 0 означает интервал провайдера
  (`profile-update-interval`), иначе 12 часов. После ошибок повтор через 5, 10,
  20 минут и далее до 6 часов. Расписание работает, пока Basalt запущен, в том
  числе в трее. После запуска просроченные подписки обновляются по очереди.
  Активное соединение при обновлении не перезапускается.
- Проверка всех загруженных серверов самими ядрами перед заменой списка.

  Ответ устаревшего фонового запроса после редактирования/удаления отбрасывается.
- sing-box JSON: VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, SOCKS, HTTP.
  Сохраняются нативные outbound-параметры, которые принимает встроенное ядро;
  selector/urltest/direct не становятся серверами. Внешние detour, endpoints,
  плагины и привязки к чужим интерфейсам отклоняются явно.
- Clash YAML: те же типы, TCP/WS/gRPC/HTTP, TLS/REALITY, ALPN, Hysteria2 obfs.
  Поддерживаются блоки, flow mappings, кавычки, комментарии, anchors/aliases
  и одиночный mapping merge. Неизвестные параметры отклоняются явно.
  Внешние proxy-providers, произвольные плагины и все возможности Mihomo
  не заявляются поддержанными. Политики/правила провайдера не импортируются:
  маршрутизация управляется настройками Basalt.
- YAML разбирается YamlDotNet 6.1.2 (net35), без десериализации CLR-объектов:
  лимит глубины 48, лимит узлов/раскрытия aliases 30000, запрет циклов и
  повторяющихся ключей. Библиотека включена в portable-пакет вместе с лицензией.

Пройдены 69 проверок плюс UI-регрессия. Конфигурации из реальных форматов
проверены командами check/test встроенных ядер x64 и x86. Устойчивость на
Windows 8/8.1 по-прежнему требует VM-испытаний. Полный визуальный прогон новой
панели и диалогов не завершён: управление окнами было остановлено пользователем.

Форматы сверялись с [sing-box](https://sing-box.sagernet.org/configuration/outbound/)

## Исправления интерфейса 0.5.1

- Векторные кнопки окна (свернуть/развернуть/восстановить/закрыть), chevrons и меню
  подписки вместо символов шрифта; переработаны значки навигации.
- Нативная часть ComboBox и оформление рисуются в один буфер. Убрана видимая
  дорисовка через CreateGraphics после WM_PAINT. Панели и список буферизованы;
  перестроение страницы выполняется с временно приостановленной перерисовкой.
- Заголовок подписки использует общую геометрию для текста, кнопок и hit testing.
  Учтён DPI, текст ограничен одной строкой с ellipsis и clipping.
  Трафик и срок действия занимают две непересекающиеся колонки.
- Обновление списка сохраняет прокрутку и выделение.

Пройдены 69 проверок модели и UI-регрессия: пустой список/индекс 65535,
длинные названия, геометрия при 100/125/150/200%, перерисовка, сохранение прокрутки.
Основной экран дополнительно просмотрен в работающем приложении. Эти проверки
не являются замером мерцания на всех видеодрайверах или испытанием Win8/8.1.

## Диагностика импорта 0.5.2

Общий отказ частичной подписки заменён подробным отчётом: формат ответа,
количество распознанных серверов, число ошибок и первые 20 конкретных причин.
Отдельное окно позволяет прокрутить и скопировать отчёт. Полные URI и UUID
в деталях маскируются; исходное содержимое подписки в отчёт не добавляется.
Частичный ответ по-прежнему не заменяет рабочую подписку автоматически.
Это исправление диагностики, а не подтверждение исправления каждого неизвестного
формата провайдера. Пройдены 59 проверок модели и UI-регрессия.

Если старая программа заняла файлы build, можно собрать отдельно:
`scripts/build.ps1 -OutputDirectory build/release-0.5.2` и упаковать через
`scripts/package.ps1 -BuildDirectory build/release-0.5.2`.
