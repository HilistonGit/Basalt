# Совместимость Basalt 0.6.0

## Стек

Оболочка — C# / WinForms / .NET Framework 4.0; современный .NET сюда не подставляется.
Для Windows 8/8.1 Framework обеспечивает подходящий базовый API, но компиляция
против его reference assemblies не заменяет тесты на самих ОС.
Qt лучше подходит для переносимого UI. Для старых Windows нельзя просто взять
актуальный Qt: Throne использует собственный legacy-вариант Qt 6.2.13 и patched Go.
Смена UI-стека не решает совместимость Go-ядер и сетевого драйвера.
Сейчас сохраняется рабочая оболочка Framework; модель, импорт и генерация JSON
отделены в Basalt.Core, Windows API — в Basalt.Windows.

Источники:
- [Throne build workflow](https://github.com/throneproj/Throne/blob/1f30af24e2de13e0735dede240e4592a93e18b64/.github/workflows/build.yml)
- [Qt 6.2 supported platforms](https://doc.qt.io/archives/qt-6.2/supported-platforms.html)
- [MetaCubeX Go](https://github.com/MetaCubeX/go)
- [Wintun: поддерживаемые Windows](https://git.zx2c4.com/wintun/about/)

## Что проверено

Поставка 0.6.0: официальные upstream legacy-бинарники Xray 26.10.21 и sing-box 1.14.4 для x86/x64; архивы проверены по закреплённым SHA256.
Пройдены 69 проверок модели, реальные проверки JSON обоими ядрами,
запуск/остановка/переподключение, SOCKS5, конфликт портов и DPAPI.
Есть отдельный TUN smoke test с локальным Shadowsocks-сервером, HTTPS-запросом
без прокси приложения, счётчиками адаптера, повторным подключением и очисткой.
Тест пройден на текущем хосте (Windows build 26100) для Shadowsocks и VLESS
через Xray, включая UDP/DNS и два подключения каждого протокола.
Его результат записывается отдельно: `build/release-0.6.0/tun-smoke-result.txt`.

**Windows 8 и 8.1 пока не испытаны. XP этим комплектом не поддерживается.**
Wintun 0.14.1 рассчитан на Windows 7 и новее. Legacy-ядра не предназначены для XP.
Оболочка Framework 4.0 сама по себе не делает полный VPN совместимым с XP.

## Подготовка VMware

Создать две отдельные VM: Windows 8 x86 и Windows 8.1 x64, желательно затем
проверить также Win8 x64 / Win8.1 x86. Использовать собственные установочные образы
и лицензии. Начать с 2 vCPU, 2–4 ГБ RAM, диска 30 ГБ, сети NAT.
Сделать snapshot после установки ОС/обновлений/корневых сертификатов, до Basalt.
Не отключать проверку TLS и подписи драйверов для прохождения тестов.
Скопировать весь portable-пакет, включая cores; не только Basalt.exe.

На каждой VM зафиксировать winver, разрядность, версию Framework и manifest ядер.
Не определять версию Windows только через Environment.OSVersion: без manifest
совместимости Windows может сообщать 6.2 даже на более новом хосте.

Порядок проверки:
1. Запуск обычным пользователем, загрузка HTTPS-подписки, проверка лимита и срока.
2. UAC для TUN, установка подписанного Wintun, TCP и UDP, DNS, IPv4 и IPv6.
3. VLESS/Trojan через Xray + sing-box, Shadowsocks/Hysteria2 через sing-box.
4. Проверить внешний IP и DNS на контролируемом сервере; проверить маршрутизацию
   доменов/CIDR/процессов и отсутствие петли к адресу VPN-сервера.
5. Сто переподключений, авария каждого ядра и оболочки; проверить остаточные
   процессы, адаптеры, маршруты и восстановление существующего системного прокси.
6. Сон/пробуждение, смена NAT-сети, недоступный DNS/сервер, длительная работа.
7. UI 1024×768, 100/125/150/200% DPI, клавиатура, длинные названия, много подписок.

Успех одного smoke test не подтверждает устойчивость при смене сети и авариях.
Привилегированная часть пока выполняется в повышенном процессе клиента;
отдельного Windows-сервиса нет. Оставшийся после аварии адаптер отключается по
журналу с уникальным именем; удаление старых отключённых устройств ещё не реализовано.
